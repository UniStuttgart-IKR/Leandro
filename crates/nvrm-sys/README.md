# `nvrm-sys` — raw bindings to the NVIDIA driver ABI

A measured struct layout per supported driver version, generated by
`cargo xtask abi` and **committed**. Every other crate reaches the driver ABI
through here; nobody transcribes a struct by hand.

The version set, the support policy and how to add a version are in
[`docs/abi-versions.md`](../../docs/abi-versions.md).

| File | What it is |
|---|---|
| `abi.toml` | hand-maintained: the versions, the footprint, the mediated core, the renames |
| `manifests/<version>.json` | generated: size, alignment and every field offset, per version. The evidence |
| `manifests/classification.md` | generated: what changed between every pair of versions |
| `versions.toml` | generated: the manifest hash and the layout module per version |
| `src/stable.rs` | generated: every name that is identical on every version |
| `src/v<NNN>.rs` | generated: one module per version, for the names that are not |
| `src/lib.rs` | generated: `DriverVersion`, `RmAbi`, `dispatch`, the layout asserts |
| `src/version.rs` | the one hand-written file: which driver is actually running |

## Building

Nothing special. There is no `build.rs` any more: the source is committed, so
a consumer needs neither libclang nor the vendored headers.

REGENERATING needs both — `cargo xtask abi` runs bindgen over
`vendor/nvidia-rm-headers/`, which `scripts/build.sh vendor-abi` fetches. The
check band verifies that a regeneration produces no diff.

## Limits, honestly

- The output is bindgen's, ugly on purpose; tidying it by hand would be
  discarded by the next regeneration, and CI would notice.
- The crate is excluded from doctests and from `cargo doc` in the check band
  (`--exclude nvrm-sys`): it is machine output.
- `assert_driver_version()` demands the ONE version this build defaults to and
  is for single-version tools. Anything that carries several uses `detect()`,
  which refuses an unmeasured version rather than approximating it.
