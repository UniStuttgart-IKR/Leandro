# Driver versions

- [`abi.toml`](../crates/nvrm-sys/abi.toml) selects versions, bound types,
  mediated layouts and acknowledged renames.
- `vendor/nvidia-rm-headers/<version>/` contains upstream headers and `PROVENANCE`.
- `cargo xtask abi` generates committed bindings, layout manifests and version
  metadata. [`src/version.rs`](../crates/nvrm-sys/src/version.rs) remains handwritten.
- Manifests record size, alignment and field offsets. Layout checks do not prove
  that a workload works on that driver or GPU.

## Current version entries

| Driver | Cargo feature |
|---|---|
| 580.178.04 | `v580` |
| 595.99.02 | `v595` |
| 610.57.04 | `v610` |
| 615.71.09 | `v615` |

- The normal default is the version in [`DRIVER_VERSION`](../DRIVER_VERSION).
- Features are additive. `--all-features` includes all configured versions;
  it does not select one layout for every caller.
- `detect()` reads the running driver and accepts an **exact configured version**
  whose feature is enabled. Unknown minors are rejected, even if their headers
  would produce an identical layout.
- `assert_driver_version()` is the stricter check used by single-version tools:
  the running version must equal the build's default.
- Policy: maintain selected supported branches through explicit entries. Do not
  assume that a branch number uniquely identifies a layout or that these entries
  always track NVIDIA's latest releases.

## Add a version

```sh
./scripts/build.sh vendor-abi <version>
# Add [versions."<version>"] to crates/nvrm-sys/abi.toml.
cargo xtask abi
cargo xtask abi --check
```

- **Identical layout:** the generator reuses stable definitions where possible.
- **Append-only change:** separate versioned definitions preserve existing field
  offsets when the containing types permit it.
- **Breaking mediated layout:** generation stops and names the changed fields.
  Review the callers before adding the requested `[versions."...".layout]`
  acknowledgement. An acknowledgement does not repair a caller.
- Layout acknowledgements apply to the mediated footprint. Changes in other
  bound types are classified in the generated manifests.
- Keep obsolete manifests as historical evidence when removing a version entry.

## Runtime selection and guest compatibility

- `nvrm::serve` selects `A: RmAbi` from the running driver.
- `NvrmDevice<A>` builds `table::build::<A>()` for that selected ABI.
- The guest validates the table format, bounds and checksum. The checksum checks
  the transferred contents; it does not prove compatibility with guest userspace.
- Stage matching NVIDIA userspace and review generated guest constants when
  changing versions. Some guest paths still depend on those constants.
- Recorded on 2026-09-14: `nvrm-genhdr` produced identical headers for 595, 610
  and 615. The 580 header differed in seven virtual-display definitions because
  it lacks `NVA083_GRID_DISPLAYLESS`. This observation is not an end-to-end gate.

## Measure a driver/GPU pair

```sh
# From Leandro, after installing the selected host driver:
export LEA_DRIVER=<version>
./scripts/build.sh vendor
./scripts/check.sh

cd ../Leandro-Test
./scripts/abi-verify.sh
./scripts/abi-verify.sh table
```

- `LEA_DRIVER` selects the rig run's driver; it does not rewrite `DRIVER_VERSION`.
- Test `abi-verify.sh` runs core software checks, the GPU gate and the ioctl matrix,
  then writes Test `matrix/abi-verify-*.json`. `table` updates the block above in
  the selected core checkout. Record both repository revisions.
- `scripts/check.sh` verifies generated ABI output and builds each
  `nvrm-sys` feature separately and together. GPU behavior needs the hardware run.
