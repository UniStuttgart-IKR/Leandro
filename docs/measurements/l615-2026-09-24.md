# The 615.71.09 switch, 2026-09-24

Step L2 of the repository split: Leandro moves its target driver from 610.57.04
to 615.71.09, the host driver installed on 2026-09-24. Branch `port/615`, created
from `port/caraxes-2026-09` (L610), local only. Nothing here was run on a GPU or
in a VM, and no host driver state was read or changed.

## What changed, and what did not

- **Bindings.** 615.71.09 already had an `abi.toml` entry and vendored headers.
  `cargo xtask abi` changed only the default: no binding, manifest or layout
  moved. `tools/build.sh vendor-abi 615.71.09` reproduced
  `vendor/nvidia-rm-headers/615.71.09` byte for byte (105 headers, 0 absent);
  its only diff was the tool path in `PROVENANCE`, which was left as committed.
- **Guest module.** `nvrm-genhdr` changed one line of `nvrm_wire.h`:
  `NVRM_DRIVER_VERSION` is `"615.71.09"`. That is the RM version string
  `virtio_nvrm` hands NVKMS, and it refuses any other `NV_VERSION_STRING`. So
  the guest modules need a rebuild and no source change. `nvrm_kapi.h` agrees
  with the 615.71.09 headers (`kapi-abi`: `nvidia_modeset_rm_ops_t` 72 bytes,
  params union at 8, 32 GPUs).
- **vhost-user-nvrm** selects its ABI at start-up (`nvrm_sys::detect()`). The
  default build carries only `v615` and refuses a 610.57.04 host. The generator
  owns the `[features]` block, so `v610` cannot be added to the default by hand
  (`abi --check` would fail). A binary that serves both hosts is built with
  `--features v610`: 221 tests pass with it.
- **Packaging.** The debs took their version constraints from `DRIVER_VERSION`
  already, but named the 610 packages literally. `@BRANCH@` (the major of
  `DRIVER_VERSION`) now fills them. At 615.71.09 the debs recommend
  `libnvidia-compute-615`, `nvidia-utils-615` and `nvidia-driver-615-open`, and
  conflict with `nvidia-dkms-615*`. This was checked by substituting the
  control files and evaluating `.#guest-deb` and `.#host-deb`; they were not
  built, because both need the 615 source fetch.
- **Matrix.** `matrix/` stays a 610.57.04 record. A catalogue needs traces and
  a verified file needs native and guest runs on the card. Neither can be
  derived from the headers, so there is no 615 matrix.
